What it is

HIM is a personal agent designed for ownership: the model, memory, tools, and conversation history run where you decide they run. The interface stays simple. The engineering sits in the harness that routes each query, sets up queryable environments instead of stuffing context into prompts, executes generated code in a sandbox, and fuses semantic and lexical retrieval. The result is an agent that handles large personal datasets without blowing up the parent context window or leaking data.

Architecture

01 · Routing

Query Router

Classifies each query by tool count, reasoning depth, privacy sensitivity, and complexity, then selects local, cloud, or recursive execution.

02 · Context

Environment Manager

Injects conversation history, memory, and preferences as queryable objects into the REPL globals. Data stays external to the prompt.

03 · Inference

Model Executor

Local Qwen 3 8B stays loaded in VRAM with an idle timeout. Cloud providers cascade on rate limits. Prompts stay near one thousand tokens.

04 · Execution

Python REPL

Sandboxed Docker container with seccomp, read-only filesystem, memory limit, and timeout. An answer dict persists across code blocks.

05 · Tools

MCP Bridge

Lazy-loads MCP servers as Python modules via a bridge with getattr hooks. Three concurrent servers max, LRU eviction after inactivity.

06 · Memory

Hybrid Memory

ChromaDB vectors plus SQLite FTS5, fused with reciprocal rank fusion. Handles paraphrase and exact identifiers in the same query.

07 · Scale

Sub-Agent System

Parallel isolated LLM workers via llm_batch. Each sees a single prompt, returns a summary, and never inherits parent history. Twenty-five to one compression.

08 · Audit

Response Handler

Formats output, stores the turn in both memory stores, and logs latency, model, tokens, cost, and success to an audit table.

Query data flow

  R --> E[Environment Manager]
  E --> M[Model Executor]
  M --> C[Generated code]
  C --> P[Python REPL]
  P --> B[MCP Bridge]
  B --> T[Tools: mail, chat, files, calendar]
  T --> P
  P --> H[Response Handler]
  H --> MEM[(Vector + Lexical Memory)]
  H --> OUT[Answer to user]

Security layers

Docker isolation. Secomp-filtered container, read-only filesystem, two-hundred-fifty-megabyte tempfs, five-hundred-megabyte memory cap.
Network allowlist. Container reaches only MCP servers. No general outbound access from generated code.
Execution timeout. Thirty seconds per code block, one second MCP startup expectation, deterministic abort.
Credential hygiene. OAuth tokens live in the OS keyring. Environment variables are fallbacks only.
Resource cap. At most three concurrent MCP servers per session, LRU-evicted to stay within two to three gigabytes.

Roadmap

Post-MVP directions: encrypted multi-device memory sync, proactive background analysis, voice interruption with streaming text-to-speech, a visual dashboard for memory and audit logs, a plugin system for community MCP servers, and federated encrypted memory sharing.

HIM is specified and documented at the architecture level. Implementation is staged module by module, starting with the router, environment manager, and sandboxed REPL.
